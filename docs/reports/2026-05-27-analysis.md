## §1 — Ranked executions

Two metrics, two slightly different orderings. The accuracy column is
computed by the analyst directly from each run's committed
`prediction_probabilities.csv` against the
`Image_Classification` ground-truth feature (`Confidence IS NULL`,
execution FZC). The AUC columns are computed inside the analyst's
notebook execution YQ2 (asset `YSM` `roc_metrics.csv`).

| Rank (Acc) | Rank (Micro-AUC) | Exec | Variant | Dataset(s) | Pred. CSV | Test acc (from CSV) | Test acc (Dev. log) | AUC (micro / macro) |
|---|---|---|---|---|---|---|---|---|
| 1 | 1 | **YAP** | `cifar10_regularized` (dropout 0.25, wd 1e-4, seed 2026) | TX0 + **XEM Validation** | YCP | **36.00%** | 37.33% | **0.789 / 0.789** |
| 2 | 2 | **XYG** | `cifar10_default` (seed 123) | TX0 (600/150) | Y0E | 34.67% | 42.00% | 0.781 / 0.779 |
| 3 | 3 | **XNE** | `cifar10_quick` (3 epochs, seed 42) | WD2 (400/100) | XQC | 24.00% | 24.00% | 0.677 / 0.712 |

**Verdict: YAP is the best run.** It wins on every measured criterion
the Analyst has access to — accuracy on the committed predictions
(36% vs 34.67%), micro-AUC (0.789 vs 0.781), macro-AUC (0.789 vs 0.779),
and it is the only run that exercises the regularized variant and the
Validation dispatch lane. The regularizer's effect is visible in the
per-class breakdown: YAP's worst-class (`deer`) is at 6.7% while XYG's
worst-class (`deer`) is at 0.0% — i.e. YAP at least *tries* on every
class, whereas XYG collapses on `deer` entirely.

**Reconciliation with tk-004.** The "test_acc" the Developer logged in
the training logs (42.00%, 37.33%, 24.00%) is the *final-epoch
test_acc reported by the training loop*. The "Accuracy" column above
is computed from the *committed* `prediction_probabilities.csv`. They
agree for XNE (24.00% vs 24.00%) but diverge for XYG and YAP. The
CSV-based numbers track *earlier* epochs of each run (XYG ~34.67%
matches the run's epoch-4 test_acc; YAP ~36.00% matches its epoch-5
test_acc). The most likely explanation is that the prediction CSV
captures model state at a different point than the final-epoch log
line — either an explicit `--save-best` checkpoint, or the CSV is
generated *before* the last optimiser step, or the model is
re-instantiated from a saved checkpoint earlier than the final one.
**This is finding `analyst/02`** — not a blocker for analysis, but
worth surfacing because the canonical "what does this run produce?"
question has two different right answers right now.

## §2 — Per-class & confusion findings

The full confusion matrices live as Execution_Asset rows on YQ2 —
`YSE` (XYG), `YSG` (YAP), `YSJ` (XNE) — and the per-experiment ROC
curves are `YS6/YS8/YSA`. The cross-experiment ROC overlay is `YSC`.

A few patterns worth flagging:

- **All three runs over-predict `frog`.** `frog`'s AUC (0.794–0.813)
  is high yet other classes get pulled into `frog` predictions —
  visible as a vertical band in each confusion matrix. Likely the
  softmax bias of an under-trained classifier; nothing wrong with the
  data.
- **YAP's regularization closes the worst-class gap.** XYG and XNE
  each have at least one class at 0% recall; YAP's worst is 6.7%
  (`deer`). For an Analyst recommending a winner to a downstream
  consumer, "no class is completely broken" is the right ranking
  signal at this dataset scale.
- **AUC and accuracy disagree at the third place.** XNE's accuracy is
  24% (basically random over 10 classes is 10%), but its micro-AUC is
  0.677 — well above the 0.5 chance line — because soft probabilities
  still rank correctly even when the argmax doesn't. The Developer's
  test_acc ranking is consistent with AUC ranking here.

## §3 — Denormalize cross-channel parity (the #246 headline)

The dataset chosen was **JZ8** (`Complete, Labeled`, 1,500 Image
members, version `0.1.0.post1.dev3`) — the largest dataset in the
catalog and the most aggressive exercise of the chunked PagedFetcher
loop that PR #246 lands.

**Direct channel** (`Dataset.list_dataset_members()`):

```
member-type buckets: ['Dataset', 'File', 'Image']
  Image: 1500
distinct Image RIDs: 1500
```

**Indirect channel** (post-#246 PagedFetcher, via
`Dataset.get_denormalized_as_dataframe`):

```python
df = ds.get_denormalized_as_dataframe(
    include_tables=["Image", "Execution_Image_Image_Classification"],
    version="0.1.0.post1.dev3",
)
# shape: (1900, 12)
# distinct Image.RID: 1500
```

| Check | Direct | Denorm (raw) | Denorm (GT-only filter) | Parity |
|---|---|---|---|---|
| Total rows | — | 1900 | 1500 | (raw includes prediction features; see below) |
| Distinct Image RIDs | 1500 | 1500 | 1500 | **match** |
| Missing (in direct, not denorm) | 0 | 0 | 0 | — |
| Extra (in denorm, not direct) | 0 | 0 | 0 | — |
| Class distribution (GT) | 10× 150 | 10× ranges from 160 to 256 | 10× 150 | **match (GT-only)** |
| Null Image.RID | 0 | 0 | 0 | — |
| Null Image_Class | 0 | 0 | 0 | — |
| Null Confidence (== GT) | — | 1500 / 1900 (78.9%) | — | (expected; null Confidence is the GT predicate) |

**Headline:** every Image RID the catalog has on JZ8 is present in
the denorm output; no row is lost, no row is duplicated. Row count
agrees: 1500 distinct Image RIDs in *both* channels. **PR #246
holds end-to-end at 1500-image scale.** This is the test plan §3.4
checkbox the e2e arc exists to tick.

**About the 1900-row raw count.** The denorm output has 1900 rows
because `Execution_Image_Image_Classification` carries *both* ground
truth (1500 rows from execution FZC, all with `Confidence is null`)
and per-image *predictions* from the three Developer training runs
(150 + 150 + 100 = 400 rows from XYG / YAP / XNE, all with confidence
scores). That's correct semantics — denormalize over a feature table
includes every feature value, not just the ground truth — but it's a
trap for an analyst expecting "one row per Image". The filter
`df[df['Execution_Image_Image_Classification.Confidence'].isna()]`
collapses to exactly 1500 GT rows with perfectly balanced 150/class.
This is a tk-005 lesson, not a finding (the denormalize spec is
explicit about cardinality, but the human-friendly default
`row_per=` could have been "Image" to make this less surprising —
that's a downstream design conversation, not a parity defect).

**Two cosmetic columns with all-null content:**

- `Execution_Image_Image_Classification.Confidence` is null on the
  1500 GT rows (it's the GT predicate); fully populated on prediction
  rows.
- `Image.Description` is null on all 1900 rows. This is a property
  of the loader (the Toronto images aren't given individual
  descriptions), not a denormalize defect.

Neither indicates a missing-row pathology.

## §4 — Conclusions

1. **Winner:** YAP (`cifar10_regularized`). It beats XYG on accuracy
   (CSV), micro-AUC, macro-AUC, and worst-class recall, and it's the
   only run that exercises the Validation dispatch lane the platform
   gained on 2026-05-26. Regularization (dropout 0.25 + weight decay
   1e-4) is the right knob for this dataset scale.
2. **The Developer's headline metric needs an asterisk.** Test
   accuracy in the training log (42% for XYG) is not what the
   committed predictions reproduce (34.67%). Both numbers are real;
   they're just measuring different epochs of the same run. Findings
   filed under `findings/analyst/02-`.
3. **#246 PagedFetcher fix is end-to-end validated.** 1500-row
   denormalize on JZ8 returned the exact set of Image RIDs the
   direct channel reports, no missing, no extra. This is the first
   e2e exercise of the fix at this scale.
4. **Caveats:** Three runs aren't enough to certify a model
   architecture — the comparison is "best of three" not
   "statistically best". A future Analyst should re-run YAP at
   multiple seeds to confirm the lift over XYG isn't a one-seed
   accident. The `cifar10_extended` 50-epoch variant was deliberately
   not run; running it would test whether the small dataset overfits
   in the way Developer tk-004 predicted.
